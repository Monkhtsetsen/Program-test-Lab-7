## 1. Ажлын орчин

- **Node.js хувилбар:** `v24.18.1`
- **Браузер:** [Firefox]

## Зорилго

Уншлагын жагсаалт веб апп дээр Session-Based Test Management (SBTM) аргыг ашиглан exploratory тест хийх, ажиглалтаа тэмдэглэх, илэрсэн согогийг баримтжуулах.

## Файлууд

- **charter.md** — тестийн төлөвлөгөө

- **session-report.md** — 60 минутын session-ийн тэмдэглэл

- **bugs/** — согогийн тайлангууд

- **evidence/** — API тестийн нотолгоо

- **screenshots/** — UI согогийн скриншотууд

## Хэсэг E: Дүгнэлт

Энэ session-ээр нийт 10 тестийн тохиолдол ажиллуулснаас 3 нь PASS, 6 нь FAIL, 1 нь баталгаагүй үр дүнтэй байв. PASS үр дүнтэй тестүүдэд хүчинтэй мэдээллээр ном нэмэх (T01), ном хайх (T07), ном устгах үед хүснэгтийн мөр болон нийт номын тоо зөв буурах (T09) үйлдлүүд багтсан. FAIL үр дүнтэй тестүүдэд хоосон номын нэр (BUG-01), хоосон зохиогч (BUG-02), зөвшөөрөгдөхгүй онууд (BUG-03, BUG-04), давхардсан ном нэмэх (BUG-06), API-д хоосон нэртэй хүсэлт илгээх (BUG-07) зэрэг орсон. T06 тестийн эхний оролдлогоор үйлдлийг санамсаргүй хоёр удаа хийсэн тул BUG-05 баталгаагүй бөгөөд батлагдсан согогийн тоонд оруулаагүй. Аяллуудаас Couch Potato нь хоосон болон буруу оролтын согогуудыг, Saboteur нь API-ийн өгөгдөл баталгаажуулалтын согогийг илрүүлэхэд үр дүнтэй байлаа. Fed-Ex аяллаар өгөгдөл устгах үед хүснэгт болон тоолуур хоорондоо нийцэж байгааг баталгаажуулсан. Урт текст, зөвхөн зайтай утга, том жижиг үсгийн ялгаа болон буруу бүтэцтэй JSON-ийг шалгаж амжаагүй тул дараагийн session-д эдгээрийг турших шаардлагатай. Лаб 1-ийн Playwright автомат тестээр хоосон талбар, буруу он, давхардсан ном болон устгалын дараах тоолуурын өөрчлөлтийг тусгай assertion бичсэн нөхцөлд шалгах боломжтой. API-ийн BUG-07-г API түвшний автомат тестээр илрүүлж болох боловч зөвхөн UI шалгадаг тестээр илрэх нь баталгаатай биш. Харин өнгө, байрлал зэрэг харагдах байдлын асуудлыг хүний нүдээр эсвэл visual regression тестээр шалгаж болно.
