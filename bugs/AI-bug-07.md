# BUG-07 — API хоосон гарчигтай ном үүсгэх хүсэлтийг хүлээн авч байна

## 1. Ерөнхий мэдээлэл

- **Bug ID:** BUG-07
- **Гарчиг:** `POST /api/books` endpoint хоосон гарчигтай номыг `201 Created` төлөвтэй үүсгэж байна
- **Severity:** High
- **Priority:** High
- **Төлөв:** Open
- **Тестлэгч:** Т.Мөнхцэцэн
- **Илэрсэн огноо:** 2026-10-21
- **Илэрсэн цаг:** 11:39
- **Тестийн төрөл:** Exploratory Testing — API Negative Testing
- **Холбогдох Charter:** CH-06 — API-ийн алдаа боловсруулах чадвар

## 2. Алдааны тайлбар

`POST /api/books` endpoint нь `title` талбар хоосон (`""`) утгатай хүсэлт хүлээн авсан боловч хүсэлтийг хүчингүй гэж үзэж татгалзахын оронд `201 Created` төлөв буцааж, шинэ номын бүртгэл үүсгэсэн.

Ингэснээр гарчиггүй ном API ашиглан системд бүртгэгдэх боломжтой байна.

## 3. Алдааг давтах алхмууд (Steps to Reproduce)

1. Аппликейшнийг ажиллуулж, серверийг эхлүүлнэ.

   ```bash
   node app.js
   ```

2. Postman эсвэл `curl` ашиглан дараах endpoint руу `POST` хүсэлт илгээнэ.

   ```text
   http://localhost:3000/api/books
   ```

3. `Content-Type: application/json` header тохируулна.

4. Дараах JSON body-г илгээнэ.

   ```json
   {
     "title": "",
     "author": "Munkhtstesen",
     "year": 2000
   }
   ```

5. HTTP status code болон response body-г шалгана.

6. Хариунд шинэ бүртгэлийн ID буцсан эсэхийг шалгана.

## 4. Хүлээгдэж буй үр дүн (Expected Result)

- API хоосон гарчигтай номын хүсэлтийг хүлээн авахгүй.
- `400 Bad Request` эсвэл `422 Unprocessable Entity` зэрэг тохирох алдааны HTTP status буцаана.
- Response body-д `title` талбар хоосон байгаатай холбоотой validation алдааны мэдээлэл байна.
- Шинэ номын бүртгэл үүсэхгүй.

## 5. Бодит үр дүн (Actual Result)

API хүсэлтийг амжилттай боловсруулж, дараах HTTP response буцаасан.

**HTTP status:**

```text
HTTP/1.1 201 Created
```

**Response headers:**

```text
Content-Type: application/json
Date: Wed, 21 Oct 2026 03:56:36 GMT
Connection: keep-alive
Keep-Alive: timeout=5
Transfer-Encoding: chunked
```

**Response body:**

```json
{
  "result": "OK",
  "id": 15
}
```

`id: 15` гэсэн шинэ бүртгэлийн дугаар буцсан нь API хүсэлтийг амжилттай үүсгэсэн гэж хариулсныг харуулж байна.

**Үр дүн:** FAIL — API хоосон гарчигтай номын өгөгдлийг хүлээн авч, шинэ бүртгэл үүсгэсэн.

Дараах нотолгооны файлуудыг хавсаргасан.

- `evidence/T10_api_empty_title.txt` — HTTP хүсэлт болон хариуны текстэн мэдээлэл.
- `evidence/T10_api_empty_title.png` — API тестийн screenshot.

## 7. Алдааны нөлөөлөл (Impact)

- Гарчиггүй, дутуу мэдээлэлтэй номын бүртгэл үүсэх боломжтой.
- Өгөгдлийн чанар болон жагсаалтын бүрэн бүтэн байдал алдагдаж болзошгүй.
- Frontend-ийн validation-ийг тойрон API руу шууд хүсэлт илгээж, буруу өгөгдөл оруулах боломжтой.
- Номын жагсаалт, хайлт болон статистикийн мэдээлэлд сөргөөр нөлөөлж болзошгүй.

## 8. Severity ба Priority-ийн үндэслэл

**Severity: High**

Backend талын validation дутуу байгаагаас хүчингүй өгөгдөл системд хадгалагдах боломжтой. Энэ нь зөвхөн UI-ийн харагдах байдлын асуудал биш, өгөгдлийн бүрэн бүтэн байдалд нөлөөлөх асуудал юм.

**Priority: High**

Ном үүсгэх API нь үндсэн функц бөгөөд шаардлагагүй, дутуу өгөгдөл бүртгэгдэхээс сэргийлэхийн тулд validation-ийг засах шаардлагатай.

## 9. Боломжит шалтгаан (Possible Cause)

API талд `title` талбарын утгыг шалгах validation байхгүй эсвэл хангалтгүй байж болзошгүй.

Тестийн үр дүнгээр шалтгааныг эцэслэн тогтоогоогүй; backend-ийн хэрэгжүүлэлтийг шалгах шаардлагатай.

## 10. Засварлах зөвлөмж (Recommendation)

1. Backend талд `title` талбар заавал байх болон хоосон биш байх нөхцөлийг шалгах.
2. Зөвхөн зай агуулсан `"   "` утгыг мөн хүчингүй гэж үзэх.
3. Validation амжилтгүй үед `400 Bad Request` эсвэл `422 Unprocessable Entity` буцаах.
4. Хүчингүй хүсэлтийн үед шинэ бүртгэл үүсгэхгүй байх.
5. Хүчинтэй болон хүчингүй өгөгдөлд зориулсан API тест нэмэх.

## 11. Retest шалгуур (Acceptance Criteria)

Засвар хийсний дараа дараах нөхцөлүүдийг шалгана.

|   № | Оролтын нөхцөл            | Хүлээгдэж буй үр дүн                        |
| --: | ------------------------- | ------------------------------------------- |
|   1 | `"title": ""`             | Хүсэлтийг татгалзаж, алдааны status буцаана |
|   2 | `"title": "   "`          | Хүсэлтийг татгалзана                        |
|   3 | `title` талбар байхгүй    | Хүсэлтийг татгалзана                        |
|   4 | Хүчинтэй гарчигтай ном    | Ном амжилттай үүснэ                         |
|   5 | Хүчингүй гарчигтай хүсэлт | Шинэ бүртгэл үүсэхгүй                       |

Засварын дараа хүчингүй хүсэлт илгээж, HTTP status болон өгөгдлийн өөрчлөлтийг шалгана. Дараа нь хүчинтэй хүсэлт илгээж, хэвийн ажиллагаа алдагдаагүйг баталгаажуулна.

## 12. Эцсийн дүгнэлт

Exploratory testing-ийн T10 API сөрөг тестийн үеэр хоосон гарчигтай ном үүсгэх хүсэлт API-д амжилттай боловсруулагдаж, `201 Created` болон `{"result":"OK","id":15}` гэсэн хариу буцаасан.

Иймээс API талын өгөгдөл баталгаажуулалттай холбоотой согог илэрсэн гэж бүртгэв. Backend validation-ийг засаж, хүчингүй өгөгдөл бүртгэгдэхгүй байгааг дахин тестээр баталгаажуулах шаардлагатай.
